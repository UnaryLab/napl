# NAPL simulation rules

This file is the canonical verification policy for the Python simulation model only; an RTL-backed change must also satisfy every gate in [RULE_IMP.md](RULE_IMP.md). Every new or changed behavior must have an automated check that fails when the behavior is wrong. Streaming-kernel tests start from [tests/template_streaming_kernel.py](tests/template_streaming_kernel.py) and single-shot trainable-kernel tests from [tests/template_single_shot_trainable.py](tests/template_single_shot_trainable.py); both call the suite drivers `streaming_suite` and `single_shot_suite` in [src/napl/utils/_shared_test.py](src/napl/utils/_shared_test.py), which also holds the shared input cloning, equality checks, and benchmark timing.

## Core gates

1. **Execution model.** A streaming module processes one timestep and increments `timestep_cur` exactly once per call; `reset()` restores the initial state, and replaying the same inputs after reset reproduces the same outputs. A single-shot module sets `streaming = False`, processes the whole tensor in one call, and keeps `timestep_cur == 0`. The base `reset()` handles the timestep and registered child modules before calling `_reset()`.
2. **Class layout.** Every public simulation class lives in its own file named exactly after the class; assisting classes and helpers live merged with what they assist (base infrastructure in `base/base.py`, cross-file module helpers in `module/_shared.py`, the metric `Analysis` container in `metric/_shared.py`). Keep each user-facing claim in the docstring closest to the API that owns it. Every class starts with a class docstring that explains its purpose and when to use it; document accepted construction inputs and configuration on `__init__()`. Each public method, property, function, and public attribute has its own user-facing docstring or doc comment covering its inputs, outputs, state changes, and use; do not duplicate these member details in the class docstring or narrate buffers, temporary tensors, helper calls, or implementation lines. Document shared reset behavior on `napl_base.reset()` and local reset behavior on each `_reset()` implementation. Put a References section at the end of the docstring containing the supported claim, formatting each paper title with reStructuredText emphasis (`*title*`). Sphinx renders the class overview, example, and references first, then a divider and the documented constructor, followed by public members in source order; it adds the inherited `napl_base.reset()` documentation without adding other inherited, private, or undocumented members. Every class derived from `napl_base` under `src/napl/sim/` defines `_reset()` explicitly; use `pass` when it has no local mutable state. In simulation Python files, separate every top-level function or class and every class method from adjacent definitions or code in the same scope with exactly two blank lines. Within each class body, place class attributes first, followed by `__init__()`, `_reset()`, `forward()`, properties, `analyze()`, and all other methods, in that order.
3. **Device coverage.** Run the full test body on every device returned by `napl.utils._shared_test.devices()`, moving both the module and the inputs. Skip a device only when the operation lacks support there, and state the reason. Streaming suite tests list every polarity supported by the operation; single-polarity operation tests state the contract reason in their test docstring.
4. **Tensor-rank coverage.** Every tensor-processing simulation class receives a direct rank-2-or-higher tensor in an automated test. A stacked timestep or cycle container does not count when iteration slices it into lower-rank tensors before the class call. Assert the resulting output and persistent-state shapes so leading dimensions cannot be dropped or flattened silently. Keep scalar and rank-1 cases when they cover distinct boundaries. A class with no tensor input or an intrinsically scalar interface is exempt only when the test states why rank coverage does not apply. The shared streaming and single-shot suites promote fidelity inputs to at least rank 2.
5. **Numerical fidelity.** Include known-answer cases and an analytic reference. Check streaming results against the stochastic-computing bound, normally proportional to `1/sqrt(N)`. Check HUB, FXP, TLUT, and Hard results against the matching PyTorch operation within the stated quantization bound. Use `torch.equal` when integer spike results must be bit-exact; otherwise state and assert the tolerance. For each tested polarity, fidelity and known-answer inputs span the legal spike range, `[0, 1]` for unipolar and `[-1, 1]` for bipolar. A mathematical domain restriction states its required input range in the test docstring.
6. **Gradients.** For trainable operations with a straight-through estimator, compare every declared input and parameter gradient with its defining equation. A finite-gradient check alone is not sufficient.
7. **Performance.** Measure the same operation once per device using identical pre-generated CPU inputs. The suite performance checks in `_streaming_performance` and `_single_shot_performance` use a large input shape with on the order of 1e5 or more elements. When fidelity inputs are smaller, the streaming suite uses `make_performance_values(polarity)` and the single-shot suite uses `make_performance_values()` for the performance inputs. `devices()` returns CPU first; save that result as the baseline and reuse it: `speedup = cpu_runtime / device_runtime`. Use `benchmark` for repeated measurements on one device. For a single device-synchronized elapsed measurement in a test, use the shared `timer(device)` context manager from `napl.utils._shared_test`; do not write manual `sync(device)` and `time.perf_counter()` blocks. Keep analysis and reporting outside the timed block unless they are part of the operation being measured:

   ```python
   from napl.utils._shared_test import timer

   with timer(device) as elapsed:
       operation()
   print(elapsed.seconds)
   ```
8. **Persistent tensor state.** Use `torch.nn.Parameter` only for trainable weights and biases. Source `weight` and `bias` tensors that define a module's computation are trainable parameters, including tensors supplied through the constructor; never register these source tensors as buffers. Keep parameter-derived values such as spike probabilities and flattened views local to `forward()` so they follow the current parameter value and device. Register every other non-trainable persistent tensor with `register_buffer`, and never update a buffer through `.data`. Use `zero_()` for zero resets and `fill_()` for constant resets. In steady-state hot paths, prefer in-place arithmetic such as `add_()`, `sub_()`, and `clamp_()` over computing a replacement tensor and copying it into the buffer. Use `copy_()` when state must snapshot caller-owned or returned data, prevent aliasing, preserve delayed state, or maintain required object identity. When the state shape changes, use `resize_()` or `resize_as_()` followed by `copy_()`, `zero_()`, or `fill_()` as appropriate. Direct reassignment to an existing buffer name is allowed when it avoids a measured hot-path cost or makes a shape-changing update simpler; detach the assigned tensor and verify registration, device migration, reset and replay, and `state_dict` serialization. Preserve buffer object identity only when the public interface requires it.
9. **Metric analysis.** Every metric `analyze()` method returns `(value, result)`, where `value` is the metric's primary per-element tensor and `result` is the complete `napl.sim.metric._shared.Analysis` returned by the shared `analyze()` helper. These derived outputs are not persistent state: keep them local to `analyze()` and do not store them on `self`, register them as buffers, or include them in `state_dict`. Callers select fields such as `result.max_absolute_index` from the returned `Analysis` object.
10. **Native operators.** When a PyTorch native operator implements the computation, use it; re-implementing an existing native operator by hand or by composing lower-level primitives is not allowed. Cross-device bitwise determinism is not a hard requirement: each device's results must meet the stated fidelity bounds, and device-to-device divergence from floating-point reduction order (including spike-trace differences it induces through hard thresholds) is accepted.
11. **Explicit imports.** Regular simulation modules and test files use explicit imports and do not use `from x import *`. Package `__init__.py` re-exports may use star imports.
12. **Encode composition.** A class that composes an `encode` instance names it `reference_encode`, suffixing the name when the class holds several, and names the per-timestep spike it returns `reference_encode_bit`.

Operands that must be independent use distinct Sobol dimensions. Fix or record the random seed and reuse the same logical inputs for the device and CPU runs.

## Verification by change type

- Streaming and single-shot trainable kernels copy the matching template, which enforces every applicable gate via the shared suite drivers.
- Encoder, decoder, metric, or base: boundary timesteps and values, tensor-rank coverage from gate 4, shapes and dtypes, device migration, reset and replay, and public state such as metric `valid` flags.
- Shared utility or public API: focused known-answer and edge-case checks and the affected callers' tests.

The default verification is the focused tests for the changed unit. Run the full sweep (`tests/sweep_test.py`) only when explicitly requested.

## Pass criteria and evidence

Every Python `test_*` function starts with a concise one-line docstring that states the behavior it verifies. Correctness, execution state, reset, and gradient checks are hard gates: they must use assertions and the verification command must exit zero; printed values do not count as a pass. An expected skip must name the unsupported device or feature. Performance evidence is required for every device; the ratio becomes a hard gate only with a stable baseline and a device-specific noise allowance. The suite drivers emit the required evidence (seed, dtype, bound versus observed error, reset and replay, timing statistics); keep their prints.
