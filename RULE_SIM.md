# NAPL simulation rules

This file is the canonical verification policy for the Python simulation model only; an RTL-backed change must also satisfy every gate in [RULE_IMP.md](RULE_IMP.md). Every new or changed behavior must have an automated check that fails when the behavior is wrong. Streaming-kernel tests start from [tests/template_streaming_kernel.py](tests/template_streaming_kernel.py) and single-shot trainable-kernel tests from [tests/template_single_shot_trainable.py](tests/template_single_shot_trainable.py); both call the suite drivers `streaming_suite` and `single_shot_suite` in [src/napl/utils/_shared_test.py](src/napl/utils/_shared_test.py), which also holds the shared input cloning, equality checks, and benchmark timing.

## Core gates

1. **Execution model.** A streaming module processes one timestep and increments `timestep_cur` exactly once per call; `reset()` restores the initial state, and replaying the same inputs after reset reproduces the same outputs. A single-shot module sets `streaming = False`, processes the whole tensor in one call, and keeps `timestep_cur == 0`. The base `reset()` handles the timestep and registered child modules before calling `_reset()`.
2. **Class layout.** Keep each user-facing claim in the docstring closest to the API that owns it. Every class starts with a class docstring that explains its purpose and when to use it; document accepted construction inputs and configuration on `__init__()`. Each public method, property, function, and public attribute has its own user-facing docstring or doc comment covering its inputs, outputs, state changes, and use; do not duplicate these member details in the class docstring or narrate buffers, temporary tensors, helper calls, or implementation lines. Document shared reset behavior on `napl_base.reset()` and local reset behavior on each `_reset()` implementation. Put a References section at the end of the docstring containing the supported claim, formatting each paper title with reStructuredText emphasis (`*title*`). Sphinx renders the class overview, example, and references first, then a divider and the documented constructor, followed by public members in source order; it adds the inherited `napl_base.reset()` documentation without adding other inherited, private, or undocumented members. Every class derived from `napl_base` under `src/napl/sim/` defines `_reset()` explicitly; use `pass` when it has no local mutable state. Within each class body, place class attributes first, followed by `__init__()`, `_reset()`, `forward()`, properties, `analyze()`, and all other methods, in that order.
3. **Device coverage.** Run the full test body on every device returned by `napl.utils._shared_test.devices()`, moving both the module and the inputs. Skip a device only when the operation lacks support there, and state the reason.
4. **Tensor-rank coverage.** Every tensor-processing simulation class receives a direct rank-2-or-higher tensor in an automated test. A stacked timestep or cycle container does not count when iteration slices it into lower-rank tensors before the class call. Assert the resulting output and persistent-state shapes so leading dimensions cannot be dropped or flattened silently. Keep scalar and rank-1 cases when they cover distinct boundaries. A class with no tensor input or an intrinsically scalar interface is exempt only when the test states why rank coverage does not apply. The shared streaming and single-shot suites promote fidelity inputs to at least rank 2.
5. **Numerical fidelity.** Include known-answer cases and an analytic reference. Check streaming results against the stochastic-computing bound, normally proportional to `1/sqrt(N)`. Check HUB, FXP, TLUT, and Hard results against the matching PyTorch operation within the stated quantization bound. Use `torch.equal` when integer spike results must be bit-exact; otherwise state and assert the tolerance.
6. **Gradients.** For trainable operations with a straight-through estimator, compare every declared input and parameter gradient with its defining equation. A finite-gradient check alone is not sufficient.
7. **Performance.** Measure the same operation once per device using identical pre-generated CPU inputs. `devices()` returns CPU first; save that result as the baseline and reuse it: `speedup = cpu_runtime / device_runtime`. Use `benchmark` for repeated measurements on one device. For a single device-synchronized elapsed measurement, use `timer`; do not duplicate its synchronization and `perf_counter` logic. Keep analysis and reporting outside the timed block unless they are part of the operation being measured:

   ```python
   from napl.utils._shared_test import timer

   with timer(device) as elapsed:
       operation()
   print(elapsed.seconds)
   ```
8. **Persistent tensor state.** Use `torch.nn.Parameter` only for trainable weights and biases. Register every non-trainable persistent tensor with `register_buffer`, and never update a buffer through `.data`. Use `zero_()` for zero resets and `fill_()` for constant resets. In steady-state hot paths, prefer in-place arithmetic such as `add_()`, `sub_()`, and `clamp_()` over computing a replacement tensor and copying it into the buffer. Use `copy_()` when state must snapshot caller-owned or returned data, prevent aliasing, preserve delayed state, or maintain required object identity. When the state shape changes, use `resize_()` or `resize_as_()` followed by `copy_()`, `zero_()`, or `fill_()` as appropriate. Direct reassignment to an existing buffer name is allowed when it avoids a measured hot-path cost or makes a shape-changing update simpler; detach the assigned tensor and verify registration, device migration, reset and replay, and `state_dict` serialization. Preserve buffer object identity only when the public interface requires it.
9. **Metric analysis.** Every metric `analyze()` method returns `(value, result)`, where `value` is the metric's primary per-element tensor and `result` is the complete `napl.sim.metric._shared.Analysis` returned by the shared `analyze()` helper. These derived outputs are not persistent state: keep them local to `analyze()` and do not store them on `self`, register them as buffers, or include them in `state_dict`. Callers select fields such as `result.max_absolute_index` from the returned `Analysis` object.

Operands that must be independent use distinct Sobol dimensions. Fix or record the random seed and reuse the same logical inputs for the device and CPU runs.

## Verification by change type

- Streaming and single-shot trainable kernels copy the matching template, which enforces every applicable gate via the shared suite drivers.
- Encoder, decoder, metric, or base: boundary timesteps and values, tensor-rank coverage from gate 4, shapes and dtypes, device migration, reset and replay, and public state such as metric `valid` flags.
- Shared utility or public API: focused known-answer and edge-case checks and the affected callers' tests.

The default verification is the focused tests for the changed unit. Run the full sweep (`tests/sweep_test.py`) only when explicitly requested.

## Pass criteria and evidence

Correctness, execution state, reset, and gradient checks are hard gates: they must use assertions and the verification command must exit zero; printed values do not count as a pass. An expected skip must name the unsupported device or feature. Performance evidence is required for every device; the ratio becomes a hard gate only with a stable baseline and a device-specific noise allowance. The suite drivers emit the required evidence (seed, dtype, bound versus observed error, reset and replay, timing statistics); keep their prints.
