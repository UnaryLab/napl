# NAPL simulation rules

This file is the canonical verification policy for the Python simulation model only; an RTL-backed change must also satisfy every gate in [RULE_IMP.md](RULE_IMP.md). Every new or changed behavior must have an automated check that fails when the behavior is wrong. Streaming-kernel tests start from [tests/template_streaming_kernel.py](tests/template_streaming_kernel.py) and non-streaming trainable-kernel tests from [tests/template_non_streaming_trainable.py](tests/template_non_streaming_trainable.py); both call the suite drivers `streaming_suite` and `non_streaming_suite` in [src/napl/utils/_shared_test.py](src/napl/utils/_shared_test.py), which also holds the shared input cloning, equality checks, and benchmark timing.

## Core gates

1. **Execution model.** A streaming module processes one timestep and increments `timestep_cur` exactly once per call; `reset()` restores the initial state, and replaying the same inputs after reset reproduces the same outputs. A non-streaming module sets `streaming = False`, processes the whole tensor in one call, and keeps `timestep_cur == 0`. The base `reset()` handles the timestep and registered child modules before calling `_reset()`.
2. **Class layout.** Every public simulation class lives in its own file named exactly after the class; assisting classes and helpers live merged with what they assist (base infrastructure in `base/base.py`, cross-file module helpers in `module/_shared.py`, the metric `Analysis` container in `metric/_shared.py`). Keep each user-facing claim in the docstring closest to the API that owns it. Every class starts with a class docstring that explains its purpose and when to use it; document accepted construction inputs and configuration on `__init__()`. Each public method, property, function, and public attribute has its own user-facing docstring or doc comment covering its inputs, outputs, state changes, and use; do not duplicate these member details in the class docstring or narrate buffers, temporary tensors, helper calls, or implementation lines. Document shared reset behavior on `napl_base.reset()` and local reset behavior on each `_reset()` implementation. Put a References section at the end of the docstring containing the supported claim, formatting each paper title with reStructuredText emphasis (`*title*`). Sphinx renders the class overview, example, and references first, then a divider and the documented constructor, followed by public members in source order, less the metadata attributes `hw`, `streaming`, `internal_encode`, `encoding_io`, `polarity_io`, `correlation_i`, and `flux_stability`, which render only on the `napl_base` page and on a class named after one of them, where that same-named member of the class itself still renders; it adds the inherited `napl_base.reset()` documentation without adding other inherited, private, or undocumented members. Execution mode is a class attribute: non-streaming classes declare `streaming = False` in their class body, while streaming classes may inherit `napl_base`'s class-level `streaming = True`. Every streaming class derived from `napl_base` under `src/napl/sim/` defines `_reset()` explicitly; a streaming class with no local mutable state uses a documented `pass`. A non-streaming class may inherit `napl_base`'s no-op `_reset()` and does not need an explicit hook; existing explicit non-streaming hooks remain legal. `napl_base.__init__()` creates `self.hw = hw_params()` with `pp_delay = 0` and an empty `timing` map. Non-streaming classes may keep these inherited defaults and do not need per-class hardware metadata; existing explicit metadata remains legal. In simulation Python files, separate every top-level function or class and every class method from adjacent definitions or code in the same scope with exactly two blank lines. Within each class body, place class attributes first, followed by `__init__()`, `_reset()`, `forward()`, properties, `analyze()`, and all other methods, in that order.
3. **Device coverage.** Run the full test body on every device returned by `napl.utils._shared_test.devices()`, moving both the module and the inputs. Skip a device only when the operation lacks support there, and state the reason. Streaming suite tests list every polarity supported by the operation; single-polarity operation tests state the contract reason in their test docstring.
4. **Tensor-rank coverage.** Every tensor-processing simulation class receives a direct rank-2-or-higher tensor in an automated test. A stacked timestep or cycle container does not count when iteration slices it into lower-rank tensors before the class call. Assert the resulting output and persistent-state shapes so leading dimensions cannot be dropped or flattened silently. Keep scalar and rank-1 cases when they cover distinct boundaries. A class with no tensor input or an intrinsically scalar interface is exempt only when the test states why rank coverage does not apply. The shared streaming and non-streaming suites promote fidelity inputs to at least rank 2.
5. **Numerical fidelity.** Include known-answer cases and an analytic reference. The suite runs both and prints the decoded error every run for the user to inspect by eye; it asserts no numerical fidelity and no known answer. The fidelity and performance runs draw their inputs at random over the legal spike range per polarity, `[0, 1]` for unipolar and `[-1, 1]` for bipolar, spanning the whole span the codec admits. A mathematical domain restriction narrows that span through the values the test's input builder returns and states its required range in the test docstring.

   The fidelity run prints the measured error only, with no bound of any kind: the streaming suite prints the RMSE over every element and the largest per-element error, and the non-streaming suite prints the largest per-element error against its PyTorch reference. No `streaming_suite` bound key exists; a test states no tolerance, ceiling, or scale for the fidelity or known-answer error, and derives no such number. The known-answer run likewise prints its measured error against the expected value and asserts nothing.

   Use `torch.equal` when integer spike results must be bit-exact; that bit-exact structural check is asserted. A `*_hub` class is non-streaming at its numeric ports and wraps a whole run of a streaming core: assert it equals the bare streaming composition it wraps with `torch.equal`, while its stochastic-computing error is run and printed. Run the non-streaming `*_fxp` classes and `butterfly_fp` against the matching PyTorch operation and print the error. The `*_hard` suffix is not an execution family and exempts nothing: each such class is run under the form it is, streaming for `sigmoid_hard`, `tanh_hard`, and `mgu_hard_mix`, non-streaming for `mgu_hard_fxp`, and whole-run for `mgu_hard_mix_hub`.
6. **Gradients.** For trainable operations with a straight-through estimator, compare every declared input and parameter gradient with its defining equation. A finite-gradient check alone is not sufficient.
7. **Performance.** Measure the same operation once per device using identical pre-generated CPU inputs. The suite performance checks in `_streaming_random_perf` and `_non_streaming_random_perf` use a large input shape with on the order of 1e5 or more elements. When fidelity inputs are smaller, the streaming suite uses `make_random_perf_values(polarity)` and the non-streaming suite uses `make_random_perf_values()` for the performance inputs. `devices()` returns CPU first; save that result as the baseline and reuse it: `speedup = cpu_runtime / device_runtime`. Use `benchmark` for repeated measurements on one device. For a single device-synchronized elapsed measurement in a test, use the shared `timer(device)` context manager from `napl.utils._shared_test`; do not write manual `sync(device)` and `time.perf_counter()` blocks. Keep analysis and reporting outside the timed block unless they are part of the operation being measured:

   ```python
   from napl.utils._shared_test import timer

   with timer(device) as elapsed:
       operation()
   print(elapsed.seconds)
   ```
8. **Persistent tensor state.** Use `torch.nn.Parameter` only for trainable weights and biases. Source `weight` and `bias` tensors that define a module's computation are trainable parameters, including tensors supplied through the constructor; never register these source tensors as buffers. Keep parameter-derived values such as spike probabilities and flattened views local to `forward()` so they follow the current parameter value and device. Register every other non-trainable persistent tensor with `register_buffer`, and never update a buffer through `.data`. Use `zero_()` for zero resets and `fill_()` for constant resets. In steady-state hot paths, prefer in-place arithmetic such as `add_()`, `sub_()`, and `clamp_()` over computing a replacement tensor and copying it into the buffer. Use `copy_()` when state must snapshot caller-owned or returned data, prevent aliasing, preserve delayed state, or maintain required object identity. When the state shape changes, use `resize_()` or `resize_as_()` followed by `copy_()`, `zero_()`, or `fill_()` as appropriate. Direct reassignment to an existing buffer name is allowed when it avoids a measured hot-path cost or makes a shape-changing update simpler; detach the assigned tensor and verify registration, device migration, reset and replay, and `state_dict` serialization. Preserve buffer object identity only when the public interface requires it.
9. **Metric analysis.** Every metric `analyze()` method returns `(value, result)`, where `value` is the metric's primary per-element tensor and `result` is the complete `napl.sim.metric._shared.Analysis` returned by the shared `analyze()` helper. These derived outputs are not persistent state: keep them local to `analyze()` and do not store them on `self`, register them as buffers, or include them in `state_dict`. Callers select fields such as `result.max_absolute_index` from the returned `Analysis` object.
10. **Native operators.** When a PyTorch native operator implements the computation, use it; re-implementing an existing native operator by hand or by composing lower-level primitives is not allowed. Cross-device bitwise determinism is not a hard requirement: each device runs the same reference and prints its measured error for inspection, and device-to-device divergence from floating-point reduction order (including spike-trace differences it induces through hard thresholds) is accepted.
11. **Explicit imports.** Regular simulation modules and test files use explicit imports and do not use `from x import *`. The subpackage `__init__.py` files under `src/napl/sim/` re-export with star imports; the `napl` package root re-exports nothing. Code and docstrings import a public simulation class or function only as `from napl.sim.<subpackage> import <name>`, where the subpackage is the one that defines the name (`base`, `operation`, `module`, `metric`, `structure`, `algorithm`), as in `from napl.sim.module import linear_mix`. The flat `from napl import <name>` and the module-object forms (`import napl.sim.operation`, `from napl.sim import operation`) never appear; `from napl import <name>` does not resolve. A file importing a public name from another napl package (`napl.sim.operation`, `napl.sim.module`, `napl.sim.metric`, `napl.sim.algorithm.*`, `napl.sim.base`, `napl.syn`, `napl.utils`) imports it at package level, never from a file inside that package. A file importing a public sibling from its own package imports it relative from the file that defines it, as in `from .stability import stability`. The private underscore modules such as `_shared` and `_shared_test` are not exported and are imported absolute from their file, as in `from napl.sim.metric._shared import analyze`. A private underscore name is likewise imported absolute from the file that defines it, as in `from napl.syn.translate import _MAPPING_PATH`; tests that target a private module or name do the same. A function-local import is reserved for breaking an import cycle.
12. **Encode composition.** A class that composes an `encode` instance names it `reference_encode`, suffixing the name when the class holds several, and names the per-timestep spike it returns `reference_encode_bit`.
13. **Config validation.** A class declares the configuration keys it requires in `key_list` and the keys it accepts but does not require in `optional_key_list`. `check_config` raises when a required key is missing, and accepts exactly the union of both lists plus `name`, raising on any other key present in the config. Put a key in `optional_key_list` only when the class works without it.
14. **Package exports.** Every `__init__.py` `__all__` under `src/napl/sim/` lists only `napl_base` and classes derived from it. Reach every other name through an explicit import from the package that defines it, as in `from napl.sim.base import hw_params`. Every subpackage `__init__.py` under `src/napl/sim/` keeps its star-import lines and its `__all__` entries alphabetically sorted; these subpackage export lists are what the sanctioned `from napl.sim.<subpackage> import <name>` imports resolve through. `src/napl/__init__.py` holds no `__all__` and re-exports nothing.
15. **Docstring scope.** Docstrings under `src/napl/sim/` are user-facing: they state what a unit is for, the configuration it accepts, how to use it, and any mechanism a caller must know to use it correctly (such as index-advance behavior a caller can trip over), and never how it works internally beyond that. Mechanism beyond that, derivations, and the reasoning behind an implementation choice go in `#` comments next to the code they justify. Every `#` comment block opens with a sentence stating the behavior of the code it annotates or the reason that code is written that way, and matches the current code. A block carrying a derivation or the reasoning behind an implementation choice continues past that opening sentence for as long as the derivation needs.
16. **Hub run contract.** Every `*_hub` class under `src/napl/sim/` declares `streaming = False`, decorates its `forward()` with `napl_sim_timesteps`, and carries its run length as `self.timestep`. One call with no `timesteps` argument is a complete fresh run: the decorator resets the class and its registered children, repeats `forward()` for `timestep` cycles on the same arguments, and returns the value of the final cycle. Any state a caller set beforehand is discarded by that reset, so two consecutive calls on the same input return the same value. A call that passes `timesteps`, and any decorated target that is not a `napl_base` module carrying `timestep`, repeats the callable that many times without resetting. Per-timestep access stays available on every module through `napl_base.forward_timestep()`, which increments `timestep_cur` once for a streaming module, runs a single timestep of the undecorated `forward()`, and never resets. Only a streaming module counts its own timesteps, so gate 1 holds for a hub on every one of these paths: its own `timestep_cur` stays at `0` and its `valid` stays false, while each registered streaming child counts the cycles the run drives through it. A test that needs the position of a run reads a child, as in `hub.core.timestep_cur`, which equals `timestep` after a bare call, the passed `timesteps` after a call that passes one, and the call count after that many `forward_timestep()` calls. Tests that read progressive refinement, compare a wrapper against a bare composition timestep by timestep, or measure one timestep for gate 7 call `forward_timestep()` instead of the class.
17. **Identity-blind kernels.** A kernel whose failure mode leaves its fidelity metric unchanged carries a check that fails when the kernel is replaced by an identity wire. The gate's criterion is that property rather than a fixed list of kernels. Rate-conserving kernels exhibit it by moving spikes in time without changing spike count: `decorr`, `shiftreg`, and `dff`. That list is not the test; the criterion is, so a kernel meets the criterion when the four shared streaming suite drivers still pass with the kernel replaced by a wire. The check asserts the property the fidelity metric cannot see, such as output correlation, spike timing, pipeline delay, or per-element structure, and its docstring or a comment beside it states which property it pins. Its shape is the author's choice: the suite's `extra_checks` slot as in [tests/operation/test_sync_skewed.py](tests/operation/test_sync_skewed.py), a standalone structural test in the same file as in the elementwise delay check of [tests/operation/test_shiftreg.py](tests/operation/test_shiftreg.py), or a bit-exact per-timestep sequence as in [tests/operation/test_sync.py](tests/operation/test_sync.py). Confirm it by returning the input unchanged from the kernel while its real state updates keep running, so the wire neuters only the emitted values, and rerunning the test file: at least one assertion must fail. Nothing enumerates the kernels the criterion applies to, so whether a new kernel meets it rests on author and reviewer judgment; the confirmation itself is mechanical and any reviewer can rerun it. A second criterion stands beside the first and carries the same check: a kernel meets it when it returns more than one output and the suite's `apply_operation` reads a strict subset of them, so a defect confined to an unread output leaves every shared driver green. `signabs`, `sync`, `desync`, `sync_skewed`, `signabs_shiftreg`, and `signabs_interleave` are examples of that criterion, not its definition: any kernel of that shape carries the check without being listed here. Confirm membership by corrupting an unread output and rerunning the test file: the four shared drivers still pass and the added check is the only failure. The identity-wire confirmation does not apply under this second criterion, since the wire changes the output the suite reads and the suite fails on it.
18. **Operation reuse.** A class under `src/napl/sim/module/` that needs a computation an `sim/operation` class already implements holds an instance of that operation and calls it instead of writing that computation inline, so each computation keeps a single owner. This gate is a modularity rule, not a performance rule: reuse is required to keep one implementation per computation, never for a runtime-cost reason, and no timing is measured for it. This gate cites code by enclosing symbol and a quoted fragment of the target line, never by line number, and the quoted fragment matches exactly one line in the cited file. `avgpool2d_ugemm.__init__()` holds the window-average adder (`self.acc = add_scale({'polarity': 'unipolar'`) and `avgpool2d_ugemm.forward()` calls it on the pooled spike count (`self.acc(popcount, entry=self.kernel_area, dim=None)`); `linear_ugemm.__init__()` holds `self.mul = mul_ugemm(` and `self.acc = add_scale({'polarity': self.polarity, 'scale': self.scale,`, and `linear_ugemm.forward()` calls both (`self.mul(input.unsqueeze(-2), self.weight)` and `self.acc(psum, entry=self.entry, dim=None)`). Reuse follows gate 11's one-way import direction: the module file imports the operation at file top with `from napl.sim.operation import ...`, and no file under `src/napl/sim/operation/` imports a module. Where operands must be independent, reuse means one operation instance per decorrelated operand on its own number-sequence dimension, not one shared instance, as in `linear_mix.__init__()`'s separate weight and bias encoders on `dim` and `dim + 1` (`self.w_encoder = encode({` and `'generator': config['generator'], 'dim': dim + 1})`) and `conv_mix.__init__()`'s padding encoder on `dim + 2` (`self.pad_encoder = encode({**cfg, 'dim': dim + 2})`). The gate covers a computation an operation class owns end to end, so tensor work that no operation class implements stays inline and is not in scope: reductions such as `sum(-1)`, shape and layout changes such as `unsqueeze`, `reshape`, `unfold`, and `index_select`, dtype conversions, and any PyTorch native operator gate 10 already requires, including the `torch.matmul` fan-in reduction in `linear_mix.forward()` (`psum = torch.matmul(xf, wf.t())`) and the bipolar XNOR count built from it (`2 * psum - xf.sum(-1, keepdim=True)`). Three conditions make reuse inapplicable, and the module states which one applies in a `#` comment beside the inline code, naming the operation it stands in for. First, the operation's interface does not offer the shape or configuration the module needs, as `encode` accepts one scalar `dim` and thresholds against one sequence, so `linear_gaines.__init__()` stacks one `encode` sequence per input feature (`w_num_seq = torch.stack([`) and `linear_gaines.forward()` compares the whole stack in a single `torch.gt` (`weight_prob, self.w_num_seq[sequence_index]`). Second, the module must ride the number sequence and index an existing operation instance already owns rather than advance a second one, as `linear_ugemm.forward()` derives its bias spike from `self.mul`'s number sequence (`self.mul.num_seq[(self.timestep_cur - 1)`). Third, reusing the operation would break its single-owner contract, because a per-timestep call would re-enter an operation instance the module already drives mid-stream. This condition is qualitative and modular, never a runtime cost: the comment names the operation the inline code stands in for and states that reuse would re-enter that instance mid-stream, with no measured cost, benchmark, number, or construction anywhere. `conv_mix.__init__()` converts the whole padding sequence to Python floats once (`self.pad_bits = [float(b) for b in pad_seq.tolist()]`) because a per-timestep operation call would re-enter the `encode` instance mid-stream, so the padding conversion stands in for `encode` and is written inline under this condition. A reviewer checks the reuse and the import direction in the module file alone: every operation the class calls is imported at file top and instantiated in `__init__()`. Whether an operation exists that covers a given inline computation is not decidable from that file, so the required comment carries the operation name and the condition, and a reviewer who doubts it reads the named operation.

Operands that must be independent use distinct Sobol dimensions. Fix or record the random seed and reuse the same logical inputs for the device and CPU runs.

## Verification by change type

- Streaming and non-streaming trainable kernels copy the matching template. The shared drivers enforce gates 1, 3, and 7 in the streaming suite, and those plus gate 6 in the non-streaming suite: execution state with reset and replay, per-device timing, and declared gradients. They run gate 5's known-answer and fidelity checks and print the measured decoded error, but assert neither, so a defect that changes the value the suite decodes is caught only when the author's own `extra_checks` or a separate test asserts it. Gate 6 has no streaming driver, since `streaming_suite` runs no gradient check. Gate 3 is partial: the drivers run every device from `devices()` but cannot tell whether the declared polarity list is complete. Gate 4 is partial: the drivers promote fidelity inputs to at least rank 2, but no driver asserts persistent-state shapes. Gate 17 carries a check that fails on an identity wire, in `extra_checks` or as a separate test; the remaining gates, including any assertion on the decoded value, are the author's to satisfy.
- Encoder, decoder, metric, or base: boundary timesteps and values, tensor-rank coverage from gate 4, shapes and dtypes, device migration, reset and replay, and public state such as metric `valid` flags.
- Shared utility or public API: focused known-answer and edge-case checks and the affected callers' tests.

The default verification is the focused tests for the changed unit. Run the full sweep (`tests/sweep_test.py`) only when explicitly requested.

## Pass criteria and evidence

Every Python `test_*` function starts with a concise one-line docstring that states the behavior it verifies. Execution state, reset, gradient, and any bit-exact structural checks are hard gates: they must use assertions and the verification command must exit zero. Numerical fidelity and known-answer are not asserted: the suite runs them and prints the measured decoded error for the user to inspect by eye, and printed values do not gate the run. An expected skip must name the unsupported device or feature. Performance evidence is required for every device; the ratio becomes a hard gate only with a stable baseline and a device-specific noise allowance. The suite drivers emit the required evidence (seed, dtype, measured error, reset and replay, timing statistics); keep their prints.

## Review tiers

Review depth follows what a change touches. A change to simulation behavior under `src/napl/sim/` or to a test that gates it takes the full review: the reviewer works through the gates the change touches and requires the mutation or bite proof those gates call for, such as gate 17's identity-wire confirmation or gate 5's bit-exact `torch.equal` equivalence for a `*_hub` class. A change confined to docstrings, `#` comments, README prose, or test message wording takes a one-pass spot check, with a verdict of at most three sentences.

Mechanical work is verified by command rather than by re-derivation. Work is mechanical when its correctness is establishable from the command output alone, without reading the diff: renames, formatting passes, and moves or anchor updates qualify. Work whose correctness depends on what the changed code means is not mechanical, however small the diff. The test is whether the attached command can fail in a way that proves the change wrong. For a rename, a formatting pass, or a docstring anchor update, the author attaches the command output that covers the claim: an `rg --hidden` sweep over the repo, the focused test run for the changed unit, or both. The reviewer confirms the commands ran and that their scope covers the claim, spot-checks the results (a zero-hit sweep proves the old name is gone, not that the new name is right), and does not repeat the change by hand.
